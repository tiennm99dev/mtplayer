## Part 5 — The compounding problem

Individually these are patchable. Together, **F1 + F2 + F4 + F5 + F6 + D1 invalidate phase 01's premise.**

Phase 01 is written as a 1-2 week bake-off that "de-risks" a known-cost task. In fact:

- Cuttlefish is documented **Linux + KVM only**; Windows is not a supported host.
- The Linaro recipe that phase 01 says to "follow" cannot be reproduced on a Windows QEMU build (F2).
- The branch it says to fetch from no longer serves API 36 (F1).
- Its decision rule's only quantitative input measures a cross-compile that isn't the real flow (F4), while the fact phase 11 depends on absolutely — crosvm snapshotting — is an unweighted matrix row and is upstream-declared unsupported with an unstable format (F5).
- Its pre-baked QEMU command line matches an **open** WHPX SMP boot-hang bug on this exact Windows build number (F6).
- And nothing can talk ADB on a clean host anyway (D1).

**The real phase-01 question is not "QEMU or crosvm."** It is: *does Cuttlefish's Android userspace reach `sys.boot_completed=1` on Windows/WHPX with vsock, ramoops/pstore nvdimm, and TAP networking all absent?* No source establishes that it can. That is unknown-cost R&D, and it is the single question v1 stands on.

## Unresolved questions for the plan owner

1. **API 36 or API 37 for v1?** F1 forces a choice: pin an Android-16 build, or re-baseline on 37 (also the next Play bar, Aug 2027). Either way API 37 must appear in the image strategy.
2. **Where does ADB come from on a clean host?** Bundle platform-tools with a license determination, or implement the ADB *device* protocol directly against the guest's adbd (which removes the 5037 dependency and the "don't disturb the user's server" hazard, but makes phase-12 auto-registration conditional).
3. **Is the guest an authenticated device or an open root shell?** Changes phases 3, 7, 12, 18.
4. **Who signs the image manifest** (D7), and is it the same key as the still-unowned code-signing certificate?
5. **If a stock WSL2 6.6/6.18 kernel already provides binderfs** (F7), does phase 17's machine-global kernel replacement — and its entire consent apparatus, prebuilt-kernel matrix, and defining risk — need to exist at all?
6. **Which artifact owns a running instance's resources** — `instances/<id>.toml` or `profiles/<name>.toml`? (D9)
7. **Should phase 01 be re-scoped** as an explicit feasibility spike with a kill criterion, rather than a bake-off between two options that may both fail?
